# FarPane Linux GPU 媒体重构（linux-host）：原生文件连接合同

实现位于 `Linux/native/file_host.rs`、`file_viewer.rs`、`files/` 和 Linux canonical protobuf patches。
这里描述正在实现的协议，不表示完整文件功能或跨客户端验收已经完成。

## 连接与权限

使用 RustDesk 文件专用登录类型，认证后才处理文件消息。该连接不订阅视频、音频或输入。
Host 必须运行于普通用户，明确开启文件共享并选择私有根目录；对端路径只相对于此根。
文件会话独立于视频 worker，GUI 最多保留一个文件窗口及一个文件专用 worker。

Host 的本机任务 token 与对端任务 ID 不同；确认只能从同 release、同用户且身份校验通过的控制接口进入。
对端的 Digest/SendConfirm 不表示本机允许写文件。逐次确认关闭时，已有目标仍要求显式覆盖批准。
共享根/设置代变化、连接结束或撤销权限使旧 owner 失效。成功的撤权确认等待文件线程清理。

## 普通文件与多选文件

一项或多项明确选择的普通文件放入一个有界 Receive 清单，最多 128 项/16 KiB。
多选的本地路径总元数据也受 16 KiB 限制；同名目标在打开传输前拒绝，不猜测改名。
每个清单项按顺序发送 Digest，收到相同索引的 SendConfirm 才读取文件内容。
每块至多 128 KiB，空文件仍通过 Digest/Confirm/Done 完整结束。
最后 Done 的索引为清单长度；Host 保存全部清单内容后回 Done ACK，Viewer 才显示完成。

## 分批目录上传

Host 在目录响应中声明 `farpane_upload_batches`。Viewer 只有看到该能力才启动分批目录上传；
不能根据版本字符串或支持目录分页就推断它支持传输分批。

Receive 请求增加 `farpane_tree`、`farpane_page`、`farpane_more`：

- 首批 page=0，path 是明确的非空目标目录；第一个清单项是 name="" 的 Dir，表示目标目录自身，支持空目录。
- 其他名称均相对于这个目录，经过分量、长度、符号链接、所有权和描述符相对寻址检查。
- 同一任务的每批至多 128 项/16 KiB，每批索引从零开始。发送端在前批 Done ACK 后才发下一批 Receive。
- SendConfirm 与 Done ACK 携带该批 page，上一批的确认不能推进当前批次。
- 后续批次必须使用相同 path、相同 tree 模式和恰好递增的 page；只在前批结束且声明 more 时接受。
- 一个目录始终对应一个 GUI 任务和一次目录批准。已有目标目录要求先批准覆盖；这个选择绑定当前任务及根范围。
- 后续批次不能借用另一目录的批准。没有覆盖权限时，遇到后来出现的同名文件会结束任务，不能静默覆盖。
- more=false 的最后一批 ACK 才表示整个目录传输结束。扫描未结束时，大小显示为未知，不以某一批的大小冒充总大小。

发送端使用有界深度遍历，只保留一个清单及一个预读条目；每次扫描调用后都可处理取消/撤权。
符号链接、特殊对象或不支持的名称不会被跟随；结束时明确报告跳过，使用独立的“部分对象已跳过”终态。
接收是逐文件提交，**不是整个目录的原子事务**。取消保留已完成的文件，移除当前未完成文件的 staging inode。

## 分批目录下载

Host 另行声明 `farpane_download_batches`，Viewer 必须看到此能力才发送 tree 类型的 Send。
Host 在本机批准前只校验所选目录，不递归扫描或读取内容；批准后仍从原私有共享根读取。
子目录不会被重新打开为权限更宽的本地选择源。发送侧保留一个有界遍历器、一个批次、一个 reader。

- FileDirectory 的 tree 标志、path、page/more 和累计 skipped 定义每批，首批同样包含空名 Dir 根条目。
- Viewer 将所有条目映射到用户选择的单个本地子目录，拒绝绝对名称、越界名称、重复项、改路径、跳页和非预期续批。
- 已有本地目录需要一次显式合并/覆盖确认；批准只属于这一任务。没有覆盖批准时后来出现的同名文件不能静默替换。
- 每项仍经过 Digest/SendConfirm；目录和空文件也有完整确认过程。SendConfirm 携带 page，旧批确认不能启动下一批的文件。
- Host 发 Done 后等待 Viewer 的同 page/同索引 Done ACK；Viewer 只在该批全部逐文件提交后确认，Host 才发送下一批。
- 最后一批保存 ACK 才使 Host 显示完成；有跳过对象时双端明确显示部分对象已跳过。普通单文件旧协议仍只在 Host 显示“已发送”。

## 资源与失败

传输层在 protobuf 解析前限制文件连接报文；解析后再限制块、清单、目录页和解压结果。
Host 最多四个文件 worker、每个最多八项任务，任务记录最多十六项；网络/磁盘之间的队列有容量和等待期限。
Owner 有 60 秒确认、120 秒空闲期限；wire 任务也有单独的 120 秒期限，覆盖本地保存完成但对端不发最后 Done 的情况。
旧批次、重复确认、过早数据和改变范围的续传均不能得到新的写权限。
单个任务的存储/清单错误清理该任务并通知对端，不必关闭整个文件连接；连接权限、传输队列或连接本身失效时仍停止整个 worker。

legacy/Mac 清单和覆盖互操作、所有畸形消息/超时/故障/并存场景仍须完成并验收。
目录扩展不能对旧 peer 静默启用；普通文件互操作也需实际跨客户端验证。
