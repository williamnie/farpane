# FarPane Linux GPU 媒体重构（hermes）：大图片传输内存

2026-10-17，在相同隔离夹具中，128 MiB PNG 双向传输的 GUI、Viewer、Host 同时采样 PSS 峰值下降约 24%。这是大字节图片传输的一项改进；首页 60 MiB、最大像素 RGBA、真实桌面和完整资源预算尚未通过。

## 改动

`Linux/native/transport.rs` 和 `0040-native-clipboard-memory.patch` 仅接入 `farpane-native` 构建。Host/Viewer 用接收到的 `Bytes` 所有者解析 protobuf，使生成的 `Bytes` 正文字段共享接收存储；旧切片解析会再次复制正文。校验、字段格式、加密、nonce、权限和队列上限保持既有语义，原始网络缓冲本身仍占内存，不能称为整条链路没有复制。

发送完成后，超过 1 MiB 消息所用的 TCP 写缓冲若已为空，则丢弃其缓冲所有者，避免长期保留图片大小的分配。只看 `capacity()` 可能漏掉 advance 后仍持有的原分配，所以判定以消息尺寸和空缓冲为准。尚有待发送字节时保留它们；普通小消息不触发回收。该释放针对 TCP，未改变 WebSocket/WebRTC 传输实现。

原生以外的构建继续使用原切片解析；没有修改 hbb_common、主机 FFmpeg、安装中的服务或 GUI 二进制。新的核心和 GUI 仍由同 release 的构建清单关联。

## 实测

| 同一夹具轮次 | 修改前同时峰值 | 修改后同时峰值 | 降幅 |
| --- | ---: | ---: | ---: |
| 0 | 1,095,666 KiB / 1,070.0 MiB | 826,010 KiB / 806.7 MiB | 24.61% |
| 1 | 1,116,417 KiB / 1,090.3 MiB | 848,645 KiB / 828.8 MiB | 23.98% |

修改前为 `Build/Linux/native-viewer-smoke/20261017T032240Z`，修改后为 `20261017T033007Z`。两轮的发送 134,217,728 字节、接收 134,217,727 字节及各自 SHA-256 完全相同；每轮 22 项实际剪贴板检查通过，包含大小限制、类型/方向权限、撤权、失焦、变化通知和画面继续。没有降低图片限额来获得结果。

每 0.1 秒采样三进程，报告的是同一条采样记录中的 PSS 合计最大值，不是三个不同时间的单进程最大值相加。单个角色的最大值并非都下降；原始分项保留在汇总中。样本每轮约 2.3–2.5 秒，仅覆盖此次传输，不能代替方案的 120 秒、三轮、交错运行及合成器/GPU 成本等正式性能验收。

图片为有效两像素 PNG 加 ancillary 填充，不代表 8K 像素解码或 RGBA 转换。测试用私有 Xvfb 和 loopback，无宿主桌面/剪贴板/GPU；不等同于 Mac、慢网络、多连接或真实加密会话的整体峰值。

两项针对性测试另外验证大正文字段共享接收存储、截断报文拒绝，以及真实加密 duplex 中大消息后的小消息完整到达、未发送完的缓冲不被清除。原生无 GPU 和旧 Flutter/GPU feature 检查通过。GUI 没有重新编译变化，SHA-256 仍为 `084241464d065df9df864c9828c46d866b530e99acaf2d239d499505eacb495e`；新原始核心为 `6af506c96c99e166b66621818927a6f67b91ed1f4d51cd17aeb48281dbb147e2`。

## 首页图形诊断

同轮补上测试专用 `native_gl_identity.c`，在 GTK 实际设置 EGL context 后记录厂商、renderer 和版本，不新建 context 或选择驱动。GTK 使用 libepoxy 的分派指针，初版普通 ELF 函数拦截没有命中，不能作为身份验证通过；修正版检查要求三个字段均实际出现。

`20261017T031800Z` 的两次真实 GPU 会话记录 Radeon 780M、radeonsi/phoenix/ACO、OpenGL ES 3.2、Mesa 26.0.8；并非 llvmpipe。首页 PSS 为 108,222/101,611 KiB（105.7/99.2 MiB）。LLVM 映射不能单独用来判断软件渲染，首页预算仍未通过。测试仅使用 renderD128、私有 Weston/Xvfb、256×128 静态内容，并持续检查已安装 FarPane 的视频连接数为零。

原始结果、版本与后续打包回归见[本轮证据](../../Evidence/LinuxHost/2026-10-17-native-clipboard-memory/README.md)。[当前测试候选](native-test-candidate.md)的源码快照已经纳入新核心改动，88,606 个归档条目逐项校验通过；旧快照与旧材料仍保留各自版本。新材料清单的 712 个包记录与 45 项机械定位问题和此前相同，仅重新绑定当前构建；完整许可审计没有因此关闭。
