# FarPane Linux GPU 媒体重构（hermes）：二次验证与输入恢复

2026-10-17。真实 Host 的 TOTP 验证已在私有视频和文件连接中通过；同时修复了格式错误的验证码使输入框消失、无法继续输入的问题。此检查不包含在 Linux 首页配置/注册新的二次验证器，也不更改用户现有身份或凭据。

## 修复

原 `.5` 中输入 `letters` 后，核心返回 `Invalid verification code`，GUI 却将 challenge 清零并隐藏输入框。连接没有通过认证，也没有画面，但用户只能退出重连。原始失败截图和事件已保留。

视频与文件界面现在先验证验证码非空、全为 ASCII 数字且不超过核心允许的 16 字节；格式错误时显示中文提示、保留输入与焦点，不发送命令、不消耗核心挑战、不操作系统密码库。实际数字值和时间有效性仍由远端 Host 验证。正常数字错误会再次显示远端挑战，正确验证码才进入画面或目录。两个界面共用同一个格式判断。

仅更改 `Linux/gui/src/{auth_secrets,viewer,file_view}.rs`；容器专用文件测试驱动补充挑战状态输出，避免把密码自动填到验证码输入框。核心、媒体源码与 FFmpeg 库没有改变。GUI Release 编译通过，9 项既有 GUI 测试通过，1 项需要专用图片夹具的既有测试按原条件跳过。没有为了此修复重编核心或 FFmpeg。

## 实测

入口为 `Scripts/linux/test-native-two-factor.sh ARTIFACT [video|files]`，视频完整格式检查加 `FARPANE_TWO_FACTOR_MALFORMED=1`。使用锁定的 secrets 测试镜像、4 CPU/12 GiB 上限、断网容器、私有 loopback/Xvfb/D-Bus/GNOME Keyring。没有宿主 GPU、桌面、服务 socket、配置或凭据挂载。

Host 在取得配置所有权前，仅在容器内设置公开 SHA1 测试向量生成的 TOTP fixture，以当前存储格式加密，未改变系统时间。已有密码测试驱动提交合成密码；验证码和取消由外部 XTest 发送到真实 GTK 控件。程序及 bundled core 均通过实际执行文件哈希绑定，不用伪造认证事件替代后端。

| 场景 | 结果 |
| --- | --- |
| 等待二次验证时取消 | 零视频帧、未保存密码、worker 回收、Host 保留 |
| 错误数字验证码 | 真实 Host 返回新挑战，之前没有画面或目录 |
| 字母、17 位数字 | 视频和文件两种界面保持输入框，可修改后继续 |
| 正确验证码 | 视频实际显示 157,664 个匹配合成远端色块的像素；文件可读取目录 |
| 密码库边界 | 二次验证成功前不保存；成功后保存连接密码，不保存验证码 |
| 文件操作 | 12 项原文件检查通过，包含分页目录、上传/下载 SHA 一致、批准、取消和 worker 回收 |
| 配置和进程 | Host 身份/认证/网络策略保留，结束 GUI 不结束 Host，无 GTK CRITICAL |

有效运行：`.5` 普通验证码 `20261017T064743Z`；`.5` 非法格式复现 `20261017T064841Z`；修复后视频 `20261017T065223Z`、文件 `20261017T065243Z`。初期三次夹具失败分别为未生成公钥的假设、误选缺少 Secret GI 的基础镜像、沿用三秒自动结束窗口；均保留原日志，分别修正为容器自身 machine-id、已有 secrets 镜像和显式结束连接，没有改变产品认证规则或时限。
