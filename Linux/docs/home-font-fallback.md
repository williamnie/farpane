2026-10-18。用户最新决定：“现在的内存已经很低了，如果无法再优化了就先这样吧”。本轮收尾已有实验，停止继续追逐首页 60 MiB；该数字保留为历史优化目标，不再作为交付阻塞项。没有宣称已达到它，也没有证明再无优化空间。当前产品字体和安装版本保留，字体精简方案暂不采用。后续优先功能缺陷与交付验收，资源增长和泄漏仍需关注。

## 动态界面的结果

复用 `.20261018.5` 原始 GUI/core 和上一轮 `fonts.wfzkyn6s` 字体，不重编应用。固定镜像、4 CPU/6 GiB、无网络、无 GPU/input/KVM、私有 Xvfb 和普通用户的隔离条件见[首页字体对照](home-font-memory.md)。本轮只在测试 GUI 中加载只读 GTK 观察库；它遍历实际可见控件，记录标签真实 Pango 排版与缺字数量，通过私有请求文件采样，不改变控件或产品代码。

正式运行 `run-crzugzjg`（命令会话 `56997`）退出 0。先分别完整预热两种字体条件的首页→设备别名→编辑窗口→回到首页，再运行 A/B/B/A 四个独立 GUI。每次用私有 core 的真实设备接口保存 `龘 靐 齉 爨 한 Ω Probe`，外部 XTest 打开实际编辑窗口、取消、删除测试设备并回到首页；身份、服务器、Host/GPU 设置和入站状态保持一致。设备目录已恢复为空，但私有配置修订号按真实写入增加。

| 初始首页 20 秒 | 11.87 / 12.50 | 10.75 / 11.22 |

四个测量进程各阶段 FD 均为 10，无子进程，SwapPss 为零。实际别名标签无缺字，未收录字符确实使用系统 Noto/DejaVu 回退；编辑框的实际文本缓冲与别名一致，取消后原别名未被改写。另有 16 项 Pango 检查通过。该观察器没有内省 GtkEntry 的实际 glyph layout，编辑框缓冲正确不能单独证明其全部字形呈现正确。

动态回退会加载更多系统字体页，静态首页约 11 MiB 的字体收益不能完整外推到交互后。这里仅一轮四进程、两个配对，且带有诊断观察库与软件 GL；总 PSS 差值包含堆和共享页波动，不是硬件实机、产品内存预算或长期泄漏结论。

## 已确认的取舍与失败

- 从 GUI 源码提取的集合没有覆盖全部后台提示：实际“系统事件监听不可用，核心仍会自行重试连接”中的“监/听”仍走原始 CJK 字体回退。因此不能仅提取 GUI 字面量便认定覆盖了整套界面。
- 实际空标签的高度从 17 变成 21 像素，后续控件有 4 像素位移。固定 SC 字体与原环境默认 JP 字体也有呈现差异；此前静态截图并非逐像素一致。
- `run-_8501rx1` 退出 1：GTK4.22 的 X11 surface ID 读取标为 deprecated，诊断库在 `-Werror` 下编译失败。仅对这项私有 Xvfb 诊断调用局部抑制弃用警告；没有关闭其他警告或改应用。
- `run-nguv3e9t` 退出 0，但只预热首页，首次打开编辑窗口的成本可能混入字体差值。保留原始结果作为探索；分析器现在要求完整动态路径预热，并已用该旧运行验证拒绝行为。正式表格只引用修正后的 `run-crzugzjg`。

三次运行的原始 smaps、JSON、日志、PNG、实际测试源码及分析器在[本轮证据](../../Evidence/LinuxHost/2026-10-18-native-font-fallback/README.md)。39 份运行源码哈希核对通过；生成观察库留在 Build，证据保存其哈希。canonical 新增 `native_font_widgets.c`、`native_dynamic_fonts.py`，扩展已有字体测试/分析入口；没有改产品默认、重新打包或安装。
