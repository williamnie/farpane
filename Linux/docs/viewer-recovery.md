# FarPane Linux GPU 媒体重构（linux-host）：Viewer 自动重连

会话页面提供“断线后使用系统密码库自动重连（最多 4 次）”开关。它只授权当前设备、当前服务器和本次逻辑会话，默认未勾选，不持久化为全局偏好。手动重新连接或替换设备创建新的授权范围；关闭窗口、断开返回和取消勾选撤销当前自动恢复。

只有实际呈现过画面的连接才能自动恢复。原生核心转发上游 `check_if_retry` 的判断，GUI 不根据中文错误文案推测是否可以重试。核心明确拒绝重试、未知本地故障、初次连接失败和 worker 崩溃保留手动操作。GPU 故障不会被自动包装成可恢复网络错误。

每次中断最多四次替换连接，退避 500/1500/3000/6000 ms。旧 worker 已回收且 GUI 的 GPU 使用已清理后，才创建下一会话；旧视图与事件不能取消或覆盖新会话。每次自动连接有 30 秒等待真实呈现的期限。认证成功不算恢复成功，首次新画面呈现才恢复正常状态并重置下一次中断的预算。已知系统准备休眠或 NetworkManager 离线时暂停启动下一尝试；现有正常视频不因 Host 重新注册而断开。

每次替换连接遇到密码请求时，最多读取一次当前服务器/公钥/远端 ID 范围内的 Secret Service 记录，并经既有受保护 IPC 提交。这个读取由上述会话开关授权，不复用原核心的配置密码、不持有覆盖整个视频会话的明文密码，也不自动解锁密码库。没有保存记录、库锁定/不可用、密码错误、二次验证或不安全连接确认时停止自动重连，保留现有人工认证界面。手动提交认证会撤销正在进行的自动恢复；没有再次确认就不继续自动读取。

取消、观察到服务器/本机身份改变或关闭会话时，会取消正在进行的密码库读取；迟到结果不能提交。自动重连沿用断线前的音频开关，避免把已关闭的接收重新打开。权限、输入、剪贴板和文件动作由新连接重新协商，不重放之前的输入或文件任务。单次临时密码对象会按现有实现清理，不能据此声称所有库、IPC 序列化和系统内存都保证完整擦除。

实现主要在 `Linux/gui/src/viewer_recovery.rs` 和既有 Viewer 页面；`Linux/native/viewer_ui.rs` 只转发核心的重试判断，不改共享网络算法。原生控制线程在观察结束后仍排空已排队的结束事件；GUI 帧通道先关闭时，为受保护控制通道保留 3 秒排空窗口（单条报文仍适用既有 3 秒传输期限），不因媒体 EOF 丢失重试判断，也不把 EOF 本身当作重试许可。手动重试仍经已有先回收、再启动的 Shell 路径。诊断只记录重试是否允许，不记录凭据。

验证使用 `Scripts/linux/test-native-viewer.sh auto-reconnect`：私有 TCP 代理切断实际流、私有密码库、私有 D-Bus 的网络提供者、真实 Host/GUI/Viewer 与 Xvfb。测试不操作宿主网络、电源、桌面、密码库、GPU 或现有服务。受控环境的通过不能代替真实网络切换、suspend/resume、驱动/合成器恢复、跨平台、长稳或内存预算验收。

2026-10-17 的最终运行 `20261017T020927Z` 已通过七轮实际 GUI 会话、八项检查：观察到离线状态后暂停并在恢复后用保存密码出图、同 GUI 回收旧 worker、取消停顿的密码库请求且不提交迟到密码、错误和缺失记录转人工认证、实际 Host 断开按钮不触发重连、四次真实替换连接后停止，以及服务器范围变化取消恢复。网络暂停依据 GUI 已观察到的 Host 状态；约一秒快照周期内尚未观察到的系统变化不承诺立即暂停。所有故障轮与修正证据保留，见[本轮记录](../../Evidence/LinuxHost/2026-10-17-native-viewer-recovery/README.md)。
